# 설계 단계

이 단계 하나만 한다. 셸 명령은 허용된 것만, 한 번에 하나씩 쓴다. `&&`·`;`·`|`로 잇지 않는다. 이으면 통째로 거부된다. `cd`는 거부된다. git 읽기는 `git -C repo ...`로 쓴다. git add·commit·push는 `git -C {job}/repo ...`로만 쓴다.

- 읽을 것: `{job}/INTENT.md`, `{job}/repo/`의 코드와 `AGENTS.md`.
- 쓸 것: `{job}/design.md` 하나. 다 쓰면 끝낸다.
- `design.md`에는 다음을 적는다.
  - 완료 기준: 무엇이 되면 끝인지, 무엇이 깨지면 안 되는지. PR 본문 Summary의 `완료 기준:` 줄에 그대로 쓸 한 줄.
  - 바꿀 파일과 이유.
  - Door(되돌리기 쉬움/어려움)와 그 근거. 애매하면 어려움이다.
  - 확인하지 않을 범위.
- 코드는 고치지 않는다. 사람이 설계를 승인하기 전이다.
- 보고 메시지·배포·push·다른 과제 폴더 수정은 하지 않는다.
- 막히면 지어내지 말고 `{job}/BLOCKED.md`에 이유를 적고 끝낸다.
- 끝낼 때는 `{job}/design.md`나 `{job}/BLOCKED.md` 중 하나를 반드시 쓴다. 앞 라운드에서 이미 끝난 일이어도 이번 결과를 새로 쓴다. 둘 다 없으면 엔진은 실패로 센다.
